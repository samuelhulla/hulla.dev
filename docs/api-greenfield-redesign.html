Chapter 01

The redesign in one decision

Make the executable schema the contract. Remove the independently modeled HTTP wire graph. Frameworks keep responsibility for HTTP mechanics; @hulla/api owns only contract semantics and the bridge between routes, handlers, clients, and integrations.

North-star rule

A route declares what crosses the network and what application code receives. Nothing else may reinterpret it.

Keep — contract-first routes

They are the portable point linking server handlers, clients, docs, and framework integrations.

Keep — local procedures

They remain validated callables for SDKs, storage, orchestration, IPC, and internal work.

Adopt — directional codecs

Zod input is the wire representation; Zod output is the application representation.

Adopt — thin framework adapters

Hono, Fastify, Express, and Fetch adapters own route registration—not a competing server runtime.

Remove — custom HTTPWireType AST

Do not separately approximate schemas, unions, defaults, catch behavior, or transforms.

Remove — implicit rich-type inference

Never reconstruct a Date merely because a runtime value or schema looks date-like.

Remove — duplicate parsing

Adapters consume the framework’s parsed values and return values for the framework to serialize.

Remove — silent degradation

Generation fails when a contract cannot be represented. It never falls back to unknown unnoticed.

◎
Product position

@hulla/api is not another backend framework. It is the consistent contract layer between the framework a team already chose and the clients and integrations they need.

Chapter 02

Two concepts, one sentence each

Radical simplicity comes from keeping the nouns honest. Do not call every callable an endpoint, and do not pretend a local function has network semantics.

01 / DECLARE

Route

A validated HTTP contract. It has method, path, locations, and response schemas—but no handler.

02 / BIND

Adapter

Binds the route tree to a server framework or a client transport without changing its meaning.

03 / CALL

Procedure

A validated local callable. It has a handler and no method or path. It can compose routes.

DX decision rule

If another process calls it over HTTP, declare a route. Otherwise, declare a procedure.

What users see

  • Contract authorUses route.get, route.post, and Zod schemas.
  • Server authorImplements a typed handler tree and mounts one framework adapter.
  • Client authorCalls methods from createClient; transport details are hidden.
  • Feature authorUses procedure for local orchestration and SDK wrappers.

What stays internal

Routes bound to a client and local procedures may share an internal Callable interface so plugins such as TanStack Query and SWR can target both. That implementation commonality should not add a third public noun.

Chapter 03

Author the wire and application types once

A Zod codec is the source of truth whenever wire and application values differ. Regular schemas remain the common case. The contract contains executable semantics; there is no adjacent wire annotation to keep synchronized. 

import { defineApi, route, router } from '@hulla/api'
import { z } from 'zod'

const dateTime = z.codec(
  z.iso.datetime(), // wire: string
  z.date(),         // application: Date
  {
    decode: (value) => new Date(value),
    encode: (value) => value.toISOString(),
  },
)

const User = z.object({
  id: z.uuid(),
  name: z.string(),
  createdAt: dateTime,
})

const CreateUser = z.object({
  name: z.string().trim().min(1),
  birthday: dateTime.optional(),
})

export const api = defineApi({
  basePath: '/api',

  users: router('/users', {
    list: route.get('/', {
      query: z.object({
        search: z.string().optional(),
      }),
      response: z.array(User),
    }),

    byId: route.get('/:id', {
      params: z.object({ id: z.uuid() }),
      response: User.nullable(),
    }),

    create: route.post('/', {
      body: CreateUser,
      response: User,
    }),
  }),
})

Type meaning

type WireUser = z.input<typeof User>
// { id: string; name: string; createdAt: string }

type ApplicationUser = z.output<typeof User>
// { id: string; name: string; createdAt: Date }

Contract rules

  • Input means wirez.input<S> is what exists after HTTP parsing and before contract decoding.
  • Output means applicationz.output<S> is what handlers receive and clients expose.
  • Codecs are optionalUse regular Zod schemas when both representations are identical.
  • Transforms are directionalOne-way .transform() is not permitted in shared routed schemas that must encode.
  • No private introspectionThe runtime calls public decode/encode APIs; build tooling uses public JSON Schema conversion.
!
Fail closed

Contract definition or generation must reject a routed schema that cannot encode. Do not emulate it, inspect private Zod internals, or silently emit unknown.

Chapter 04

One parse, one contract pass

JSON parsing and schema decoding are different operations. The framework turns bytes into JavaScript; the contract validates that value and converts it into the application representation.

Request direction

CLIENTApplication valueDate, rich objects, validated intent.
ZODEncodeValidate output side; produce JSON-safe input side.
FRAMEWORKJSON transportStringify, send, parse exactly once.
ZODDecodeValidate wire side; handler receives application values.

Response direction

SERVERHandler resultMust satisfy the application side of the response.
ZODEncodeValidate and produce the response wire representation.
FRAMEWORKJSON transportSerialize, send, and parse once on the client.
ZODDecodeClient receives the same application type as the handler returned. 
// Client request
const wireRequest = await z.encodeAsync(route.body, applicationBody)

// Server request
const handlerBody = await z.decodeAsync(route.body, frameworkParsedBody)

// Server response
const wireResponse = await z.encodeAsync(route.response, handlerResult)

// Client response
const result = await z.decodeAsync(route.response, parsedResponse)

An implementation should select synchronous operations when the schema is synchronous and async operations only when needed. Route plans are compiled once at initialization, so that decision is not rediscovered per request.

Chapter 05

Keep the package interface small

Public exports should describe user decisions, not internal machinery. Contract authors need routes; feature authors need procedures; adapters need one binding API.

@hulla/api

defineApi, router, route, procedure, defineProcedures, public types.

@hulla/api/client

createClient, fetchTransport, combine, client errors and request options.

@hulla/api/server

implement, handler inference, shared error normalization, adapter-facing primitives.

@hulla/api/zod

Optional, tested codecs for ISO dates, bigint strings, base64 bytes, URL values, and decimals.

@hulla/api-hono

serveHulla for Hono route registration and context bridging.

@hulla/api-fastify

serveHulla with Fastify lifecycle integration and optional schema compilation.

@hulla/api-express

serveHulla for Express request locations, response handling, and error middleware.

hulla CLI

Contract checks, OpenAPI emission, portable clients, compatibility reports, and watch mode.

Dependency direction

Core knows nothing about frameworks, Node, databases, query libraries, or generators. Every optional integration depends inward on the small contract and callable interfaces.

Chapter 06

Handlers are implementations, not contracts

Keep browser-safe route declarations separate from server code. The implementation tree is checked structurally against the route tree and gives each handler only the locations declared by that route. 

import { implement } from '@hulla/api/server'
import { api } from '@company/api-contract'
import { db } from './db'

export const handlers = implement(api, {
  users: {
    list: async ({ query, context }) => {
      return db.users.list({
        search: query.search,
        viewerId: context.session.userId,
      })
    },

    byId: async ({ params }) => {
      return db.users.find(params.id)
    },

    create: async ({ body }) => {
      // body.birthday is Date | undefined
      return db.users.create(body)
    },
  },
})

Hono adapter

import { Hono } from 'hono'
import { serveHulla } from '@hulla/api-hono'
import { api } from '@company/api-contract'
import { handlers } from './api.server'

const app = new Hono()

serveHulla(app, {
  api,
  handlers,
  context: async (context) => ({
    requestId: context.get('requestId'),
    session: await readSession(context.req.raw),
  }),
})

Adapter contract

  • Register onceCompile the route tree, path parameters, schema direction, and handler lookup at startup.
  • Parse onceUse the framework’s body, params, query, and headers. Never re-read an already parsed body.
  • Decode onceDecode each declared location through its contract schema before calling the handler.
  • Encode onceEncode the handler result through the selected status schema before handing it to the framework.
  • Preserve escape hatchesHandlers may return an explicit raw response for streaming, redirects, files, or framework-native behavior.
↯
Do not normalize the entire framework

Adapters should bridge context and request locations, not hide every framework feature. A raw response escape hatch keeps the abstraction honest and prevents a lowest-common-denominator server API.

Chapter 07

Client calls mirror declared locations

Explicit params, query, and body objects trade a few characters for stable calls, straightforward OpenAPI mapping, and no location-guessing algorithm. 

import { createClient } from '@hulla/api/client'
import { api } from '@company/api-contract'

export const client = createClient(api, {
  baseUrl: 'https://api.example.com',
  headers: () => ({ authorization: readAccessToken() }),
})
const user = await client.users.byId({
  params: { id: userId },
})

const created = await client.users.create({
  body: {
    name: 'Samuel',
    birthday: new Date('1995-01-01'),
  },
})

created.createdAt // Date — decoded by the shared response schema

Query and path serialization

Query and path values are textual in HTTP. Their schemas should therefore use codecs when the application value is not a string. The Zod integration may export tested conveniences without inventing a new protocol. 

import { httpCodecs } from '@hulla/api/zod'

route.get('/search', {
  query: z.object({
    page: httpCodecs.integer.optional(), // string ↔ integer
    archived: z.stringbool().optional(),  // string ↔ boolean
  }),
  response: z.array(User),
})

The fetch transport calls z.encode before constructing the URL and body, then z.decode after parsing a successful response. It must not apply an additional generic rich-value serializer.

Chapter 08

Procedures stay useful without pretending to be routes

Preserve the strongest non-HTTP capability: validated callables that wrap SDKs, storage, composition, and internal work. Their schemas use ordinary forward parse semantics because there is no network direction. 

import { defineProcedures, procedure } from '@hulla/api'
import { z } from 'zod'

const Session = z.object({
  userId: z.uuid(),
  expiresAt: z.date(),
})

export const session = defineProcedures({
  current: procedure({
    output: Session.nullable(),
    handler: () => readSessionFromStorage(),
  }),

  refresh: procedure({
    input: z.object({ force: z.boolean().optional() }),
    output: Session,
    handler: ({ input }) => authSdk.refreshSession(input),
  }),
})

Composition

export const dashboard = defineProcedures({
  overview: procedure({
    input: z.object({ userId: z.uuid() }),
    output: Dashboard,
    handler: async ({ input }) => {
      const [user, activity] = await Promise.all([
        client.users.byId({ params: { id: input.userId } }),
        analyticsSdk.activity(input.userId),
      ])

      return { user, activity }
    },
  }),
})

Plugin compatibility

Client-bound routes and local procedures implement the same internal metadata hooks, so integrations can expose identical helpers without conflating their declaration models: 

client.users.byId.$tanstack.queryOptions({ params: { id } })
session.current.$tanstack.queryOptions()

Chapter 09

Monorepos are convenient, not required

Exact codec behavior requires executable contract code on both sides. That code can arrive through a workspace package, a published package, or a Git dependency. Standalone generation is a distinct portability mode.

Mode Contract location Client result Codec capability
Monorepo packages/api-contract Imports live contract Arbitrary codecs
Separate repositories Published @company/api-contract Installs versioned contract Arbitrary codecs
Standalone generated Server repository Installs generated client Wire types or recognized codecs
Client-only Client repository Defines contract for external API Whatever contract contains
Server-only Beside server implementation No client artifact Full server codec behavior

Recommended non-monorepo workflow

server-repository/ ├── packages/api-contract/ # browser-safe package ├── apps/server/ └── .github/workflows/publish-contract.yml web-repository/ └── package.json # depends on @company/api-contract@^3

Portable generation boundary

A standalone client can derive the wire schema through z.toJSONSchema(schema, { io: 'input' }). It cannot serialize arbitrary JavaScript codec functions. The CLI therefore supports three explicit outcomes:

  1. Portable wire clientGenerated calls expose wire types such as ISO strings. Maximum interoperability.
  2. Recognized codec clientStable codec identifiers reconstruct tested codecs shipped by @hulla/api/zod.
  3. Contract-dependent clientGenerated ergonomic wrappers import the published executable contract package.
!
No invisible downgrade

The selected generation mode is part of configuration and generated metadata. A custom codec in a wire-only build causes a named build error unless the user explicitly chooses wire output.

Chapter 10

Build a tiny directional kernel

The greenfield core needs no Zod AST walker. It needs an adapter capable of decoding an unknown wire value, encoding an application value, and reporting normalized issues.

Internal schema interface

export interface DirectionalSchema<Wire, Application> {
  decode(value: unknown): Application | Promise<Application>
  encode(value: Application): Wire | Promise<Wire>
  issues(error: unknown): readonly ContractIssue[] | undefined
  jsonSchema?(direction: 'wire' | 'application'): unknown
}

export interface ContractIssue {
  path: readonly PropertyKey[]
  message: string
  code?: string
}

The public release may intentionally be Zod-first, while the internal interface prevents Zod-specific error and execution assumptions from leaking into clients, adapters, and plugins. Standard Schema can be supported later for one-way procedures without claiming bidirectional encoding it does not expose.

Route descriptor

export interface RouteDefinition {
  readonly kind: 'route'
  readonly method: HttpMethod
  readonly path: string
  readonly params?: DirectionalSchema<unknown, unknown>
  readonly query?: DirectionalSchema<unknown, unknown>
  readonly headers?: DirectionalSchema<unknown, unknown>
  readonly body?: DirectionalSchema<unknown, unknown>
  readonly responses: ReadonlyMap<number | 'default', DirectionalSchema<unknown, unknown>>
}

Compile a route plan once

type RoutePlan = {
  method: HttpMethod
  pattern: URLPattern
  decodeRequest(locations: RawLocations): Promise<HandlerInput>
  encodeResponse(status: number, value: unknown): Promise<unknown>
  execute(input: HandlerInput, context: unknown): Promise<HandlerResult>
}

const plans = compileRoutes(api, handlers) // startup, never per request

Response model

Start with one success schema for simple DX, but model status-aware responses internally from day one. A later public extension can remain additive: 

byId: route.get('/:id', {
  params: z.object({ id: z.uuid() }),
  responses: {
    200: User,
    404: Problem,
  },
})

Chapter 11

Optimize away duplicate work, not guarantees

JSON serialization is the baseline of a JSON API. The redesign’s performance goal is to eliminate @hulla/api-specific full-tree passes and defer optimized serialization to the selected backend framework.

Boundary Required work Owner Rule
Client request Encode + stringify Contract + fetch transport One of each
Server request Parse + decode Framework + contract One of each
Server response Encode + stringify Contract + framework One of each
Client response Parse + decode fetch transport + contract One of each

Required performance properties

  • No wire walkRemove recursive encodeHTTPBodyValue/decodeHTTPBodyValue passes.
  • No per-request compilationPaths, handlers, status schemas, and sync/async strategy compile at adapter registration.
  • No duplicate JSON parseFramework adapters consume already parsed body values where the framework provides them.
  • No runtime schema generationOpenAPI and JSON Schema conversion happens in build tooling or startup-only paths.
  • Streams bypass JSONRaw response escape hatches do not enter codec or JSON pipelines.

Benchmark gates

Benchmark representative small objects, 1,000-item lists, and 1 MB payloads against direct framework routes. Track latency and allocations separately. Do not market absolute benchmark numbers; enforce a regression budget in CI after a baseline is established.

≈
Expected shape

Codecs add conversion callbacks during the validation traversal, not another independent traversal. The meaningful premium is runtime validation itself—and that is one of the package’s explicit guarantees.

Chapter 12

Make failure a stable part of the contract

Error transport must remain small and framework-neutral. Detailed validator internals belong in server logs; clients receive a stable location, code, request identifier, and normalized issue list when configured. 

type ApiProblem = {
  type: string
  title: string
  status: number
  code: string
  requestId?: string
  issues?: readonly {
    location: 'params' | 'query' | 'headers' | 'body' | 'response'
    path: readonly (string | number)[]
    message: string
  }[]
}

Compatibility metadata

Every emitted contract artifact includes a format version, package version, content hash, generation mode, and codec identifiers. The server may publish the contract hash in a response header for development-time mismatch warnings; production behavior remains semver- and API-compatibility-driven. 

{
  "formatVersion": 1,
  "packageVersion": "3.0.0",
  "mode": "wire",
  "hash": "sha256:…",
  "codecs": ["hulla.iso-date-time@1"]
}

Chapter 13

Test laws, not just examples

The removed wire layer accumulated edge cases because examples cannot prove a serialization protocol. The smaller codec design should still be verified across direction, frameworks, runtimes, and generated artifacts.

Core laws

// For every supported application value:
decode(encode(application)) ≈ application

// For every canonical wire value:
encode(decode(wire)) === canonicalWire

// Framework adaptation must not alter semantics:
hono(route, value) === fastify(route, value) === fetch(route, value)

// Direct client + server agreement:
clientResult === decode(responseSchema, encode(responseSchema, handlerResult))
Zod primitives, nested objects, arrays, tuples, unions, defaults, optionals, nullable values
Sync and async codecs, refinements, and explicit rejection of one-way transforms
Path escaping, repeated query keys, empty values, Unicode, and reserved characters
Malformed JSON, wrong media type, oversized body, aborted request, and stream failure
Response status selection, no-content responses, typed errors, redirects, and raw responses
Node, Bun, browser, React Native, edge runtime, and framework adapter matrices
Standalone wire clients versus shared-contract clients for the same fixture API
Public export and browser-bundle checks preventing Node-only code from leaking into contracts

Golden reference project

Maintain one small CRUD contract exercised through every adapter and both client modes. The fixture must include ISO date codecs, query codecs, binary/raw response escape hatches, typed errors, authentication context, TanStack Query helpers, and an intentionally incompatible previous contract.

Chapter 14

Build the thin waist first

Avoid rebuilding every existing integration before proving the new contract direction. Each phase should ship an executable vertical slice and close with an explicit removal decision.

PHASE 00Freeze the brief

Record public nouns, non-goals, route schema direction, portable client modes, and performance baseline.

PHASE 01Directional core

Implement route definitions, schema adapter, normalized issues, and definition-time validation. No HTTP yet.

PHASE 02Fetch vertical slice

Bind one contract to a Fetch server and client using one parse/decode/encode/stringify sequence.

PHASE 03Framework adapters

Add Hono first, then Fastify and Express. Verify identical golden-fixture behavior.

PHASE 04Procedures + plugins

Reintroduce local procedures and the common callable hook used by TanStack Query and SWR.

PHASE 05Portable artifacts

Emit OpenAPI/JSON Schema wire contracts, hashes, codec IDs, and a wire-only generated fetch client.

PHASE 06Rich generated mode

Add recognized codec reconstruction and contract-dependent wrappers only after wire mode is stable.

PHASE 07Ecosystem migration

Port TanStack DB, Drizzle, auth examples, docs, and project templates against public APIs only.

PHASE 08Remove the old protocol

Delete custom wire conversion after parity fixtures pass. Do not run both architectures indefinitely.

Phase exit gates

  • 01 → 02A nested codec contract encodes and decodes without private schema introspection.
  • 02 → 03Fetch client/server round-trip passes and benchmark shows no custom full-tree pass.
  • 03 → 04Hono and Fastify produce identical values and normalized errors for the golden contract.
  • 05 → 06Wire artifacts are deterministic, diffable, and compatibility-checkable.
  • 07 → 08Every supported use case has a new-architecture example and public migration note.

Migration ergonomics

route('PATCH', '/:id')
  .input(z.object({ id: z.number(), title: z.string() }))
  .output(Todo)
  .handler(handler)
update: route.patch('/:id', {
  params: z.object({ id: httpCodecs.integer }),
  body: z.object({ title: z.string() }),
  response: Todo,
})
update: ({ params, body }) =>
  todos.update(params.id, body)

The migration is intentionally explicit. It removes the need to guess whether fields belong in path, query, or body and makes generated OpenAPI behavior a direct reflection of the declaration.

Chapter 16

Know when the redesign is finished

The redesign is complete when the simpler model is true in code, documentation, generated artifacts, and runtime behavior—not merely when a new API exists beside the old one.

A contract package contains no server-only dependencies and can be imported by browser and React Native builds.
A Date codec round-trips client → server → client with both application sides receiving Date.
A wire-only standalone client receives documented wire types and never implies custom codec behavior.
Hono, Fastify, Express, and Fetch adapters pass the same golden route suite.
Every request body is parsed once; no custom recursive wire traversal remains.
One-way transforms and unportable custom codecs fail with actionable build errors.
Server input and output validation errors use one stable, framework-neutral problem shape.
Routes and procedures expose the same integration hooks without sharing public declaration terminology.
Contract artifacts are deterministic and compatibility differences are available in CI.
The old wire converter, identity client schema, and silent output fallback have been removed.
Documentation teaches the route/procedure decision in one sentence and shows all five deployment modes.
Benchmarks and allocation profiles are recorded against direct framework baselines.
Final test

Can a user explain the complete system without mentioning an internal wire type?

Recommended first pull request

Do not begin by porting the existing generator. Create a new experimental package containing only defineApi, route, a Zod directional adapter, one Fetch server binder, and one fetch client. Prove a nested Date codec round-trip and record its call graph and benchmark. Everything else should earn its way back into the design after that slice is trustworthy.
