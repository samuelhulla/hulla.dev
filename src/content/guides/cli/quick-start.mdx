Add a Button to an Astro page using the `hulla` CLI. The command copies the component into your project, where you can edit its source.

## 1. Install the CLI

Install the CLI as a development dependency in the application. The exact version pin keeps team members and CI on the same CLI release; the `hulla` CLI itself requires Bun at runtime.

import DocsPackageManagerCommand from '@/components/docs/DocsPackageManagerCommand.astro'

<DocsPackageManagerCommand
  commands={{
    bun: 'bun add -D hulla@0.3.0',
    npm: 'npm install --save-dev hulla@0.3.0',
    pnpm: 'pnpm add -D hulla@0.3.0',
    yarn: 'yarn add -D hulla@0.3.0',
  }}
/>

Verify the installed executable before changing the project. These equivalent commands run the same pinned version through each package manager; Bun must be available even when the project uses npm, pnpm, or Yarn.

<DocsPackageManagerCommand
  commands={{
    bun: 'bunx hulla@0.3.0 --version',
    npm: 'npx hulla@0.3.0 --version',
    pnpm: 'pnpm dlx hulla@0.3.0 --version',
    yarn: 'yarn dlx hulla@0.3.0 --version',
  }}
/>

The command prints `hulla v0.3.0`. Keep that exact version in your project so another install uses the same CLI behavior.

Package scripts can find a locally installed `hulla` executable automatically. For the terminal commands below, add the project's executable directory to your current shell's search path. Run this from the project root:

```sh
export PATH="$PWD/node_modules/.bin:$PATH"
```

## 2. Initialize project settings

From the project root, create `.hulla/hulla.json`. The `--yes` flag accepts confirmations and prevents prompts; for this initialization, the CLI detects the package manager and records its package scripts.

```sh
hulla init --yes
```

In a workspace, initialization can inherit its package manager from the containing declared workspace. See [package-manager detection](/docs/cli/configuration#package-managers-in-workspaces).

The success signal is a new `.hulla/hulla.json` containing the package scripts and references to subsystem configuration. Commit this file so local development and automation use the same choices.

## 3. Configure and add a component

Run UI setup from the same project to choose the registry, framework, component paths, and support files. Then add a component by its registry name; specify the framework whenever the registry contains that component in more than one target.

```sh
hulla ui init
hulla ui add --framework astro button
```

The add command copies the Astro button's files and any declared dependencies or support files into the configured paths. Review the changed files and run the application's build or type checks so missing peer setup is visible in your own project. Use [UI components](/docs/cli/ui) for other framework targets.

Check the recorded UI paths, package entrypoints and peers before using the component:

```sh
hulla ui --check
```

A successful check returns exit code 0. Continue running the app's own build and type checks; [integration diagnostics](/docs/cli/reference#check-installed-integrations) do not render components or test connectivity.

## 4. Put the component on a page

The files are installed; now use them. Follow [Build a reading counter](/guides/ui/quick-start) to compose Card and Button into a working Astro page. You can skip its UI initialization step because you've already done it here.

> [!WARNING] Review before accepting overwrites
> `--yes` accepts confirmations, including replacement or deletion where a command supports them. Leave it off while exploring a setup. In [automation](/docs/cli/automation), specify component names and framework targets explicitly.

Use [UI components](/docs/cli/ui) for registry pinning and updates, or [Configuration](/docs/cli/configuration) to understand the generated settings.
