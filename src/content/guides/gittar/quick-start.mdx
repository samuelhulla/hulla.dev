## 2. Copy the repository

Create `download.ts` at the project root. Keeping the cache in this project makes it easy to inspect the two directories:

```ts filename="download.ts"
import gittar from '@hulla/gittar'
import { resolve } from 'node:path'

const snapshot = await gittar({
  url: 'hulladev/gittar',
  branch: 'master',
  cacheDir: resolve('.cache/gittar/master'),
  outDir: resolve('downloaded-template'),
})

console.log(snapshot.fromCache ? 'Used cache' : 'Downloaded')
console.log(`Copied ${snapshot.files.length} files to ${snapshot.outDir}`)
```

`url` selects the repository. `branch` selects the ref to download. `outDir` keeps the editable copy separate from the [cache](/docs/gittar/caching).

> [!WARNING] Choose an empty destination
> Copying uses `cp -R` and can replace files with matching names. Use a new directory for this tutorial. Repeated copies don't remove files that disappeared upstream.

## 3. Run it twice

Run the script with Bun, even if you used another package manager to install it:

```sh
bun download.ts
```

The first run prints `Downloaded` and a file count. Open `downloaded-template/package.json`: it should name `@hulla/gittar`. The cache directory contains the full extracted repository and its metadata.

Run the same command again. If the remote branch hasn't changed and the cache is intact, it prints `Used cache`. The default policy still contacts the remote to check the commit; a cache hit doesn't mean an offline run.

## 4. Change the policy

Add this property to the same config object when you want to reuse the local snapshot without a remote freshness check:

```ts
update: 'never',
```

Run `bun download.ts` again. It uses the existing cache. On a fresh machine, `never` still downloads because no snapshot exists yet.
