Build a React task list backed by PostgreSQL. Clicking **Add task** saves a row;
every open copy of the page receives the updated list without reloading.

## Prepare the project

Start in a React TypeScript Vite app with Zod and the
[database development tools](/docs/db/installation#local-development-requirements).
Keep the Vite entrypoints `src/main.tsx` and `src/App.tsx`. This guide lets `dev`
own local PostgreSQL, so leave `DATABASE_URL` unset. The package supplies the
development runtime, compiler and database executable.

The generated modules use explicit `.ts` imports. Keep
`compilerOptions.allowImportingTsExtensions` enabled in `tsconfig.app.json`.

> [!WARNING] Local demo, public functions
> These declarations don't authenticate callers. Use a local development database with disposable data. Add [authentication](/docs/db/authentication) before using private data.

Create `db/schema.ts` at the project root. The table gets a generated `id`; new
tasks default to `completed: false`:

```ts filename="db/schema.ts"
import { defineSchema, defineTable, v } from '@hulla/db'

export const schema = defineSchema({
  tasks: defineTable({
    title: v.string(),
    completed: v.boolean().default(false),
  }),
})
```

Create `db/tasks.ts`. The query returns rows; the mutation inserts one row in a
transaction and returns it:

```ts filename="db/tasks.ts"
import { schema } from './schema'
import { z } from 'zod'

export const list = schema.query((ctx) =>
  ctx.db.select('tasks').orderBy('title').limit(100)
)

export const create = schema.mutation({
  input: z.object({ title: z.string().min(1) }),
  handler: (ctx, input) => ctx.db.insert('tasks', input),
})
```

Register that module once in the server entrypoint. The catalogue determines
which queries and mutations the service exposes.

```ts filename="db/server.ts"
import { postgres } from '@hulla/db-postgres'
import { schema } from './schema'
import * as operations from './tasks'

export const db = postgres({ schema, functions: operations })
```

Create `db.config.ts` at the project root to let the Vite origin reach the service.
It points to the server entrypoint you just wrote.

```ts filename="db.config.ts"
import { defineConfig } from '@hulla/db/config'

export default defineConfig({
  schema: './db/server.ts',
  database: { server: {} },
  service: { origins: ['http://localhost:5173'] },
})
```

From the app directory, start the database development server.

<DocsPackageManagerCommand

`dev` starts bundled PostgreSQL, initializes the local schema, generates the function
bindings and starts the service at `http://127.0.0.1:3001`. Leave this terminal
running and add `.hulla/` to your application's `.gitignore`; saved data lives there.

Saving supported schema changes applies them automatically and reloads the service.
Existing rows and IDs are preserved. Invalid declarations or unsupported changes
leave the watcher waiting for corrected source. See [changing an existing schema](/docs/db/schemas#change-an-existing-schema).

Create `src/db.ts` and use the service URL printed by `dev`. The generated

```ts filename="src/db.ts"
import { createClient } from '../db/_generated/server/_client'

export const client = createClient({ url: 'http://127.0.0.1:3001' })
export const api = client.functions
```

Keep your Vite `src/main.tsx`. It mounts the screen you will write in the next
step. The browser imports `src/db.ts` to use the public service URL. The PostgreSQL
connection stays in `db/server.ts`. See [connection ownership](/docs/db/runtime#connect-browser-functions).

Replace `src/App.tsx`:

```tsx filename="src/App.tsx"
import { useMutation, useQuery } from '@hulla/db-react'
import { api } from './db'

export default function App() {
  const tasks = useQuery(api.list)
  const add = useMutation(api.create)
  return (
    <main>
      <h1>Tasks</h1>
      {tasks.status === 'pending' && !tasks.data && <p>Loading…</p>}
      {tasks.status === 'error' && <p>Could not load tasks.</p>}
      <ul>
        {tasks.data?.map((task) => (
          <li key={task.id}>{task.title}</li>
        ))}
      </ul>
      <button
        onClick={() => {
          void add({ title: 'My first task' })
        }}>
        Add task
      </button>
      {add.state.status === 'error' && <p>Could not save the task.</p>}
    </main>
  )
}
```

In a second terminal, start Vite on the origin allowed by your config:

Open `http://localhost:5173` in two tabs. Click **Add task** in one. Both lists
update after the commit, and the task remains after a reload. An empty database
starts with an empty list; there is no seed or local replica to initialize.

## Build on this result

Use [schemas](/docs/db/schemas) to add fields and constraints,
[queries and mutations](/docs/db/functions) to add input and shared guards, and
[authentication](/docs/db/authentication) before handling private data.
For SSR and framework-specific entrypoints, choose a
[full-stack recipe](/docs/db/meta-frameworks). If your app only needs server-side
database access, start with [direct `db` operations](/docs/db/database) instead.
