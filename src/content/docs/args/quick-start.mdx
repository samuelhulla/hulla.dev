This guide builds a TypeScript CLI that accepts a name and an optional greeting. The parser returns values when they are present; your code supplies fallbacks for omissions and produces the output.

## Install the package

Run the package-manager command in the application package that will own the CLI. Zod is a peer dependency, used for the parser's built-in schemas and the custom validation shown later. This guide uses Bun to run the TypeScript file directly.

## Define and run the command

Save this as `src/cli.ts`. Bun's `argv` includes the executable and script path, so `argv.slice(2)` leaves only the words supplied by the user. This parser opts into case-sensitive matching, so option names must match their declared casing.

```ts
import { option, parser, positional } from '@hulla/args'
import { argv } from 'node:process'

const cli = parser({
  name: 'greet',
  arguments: [positional({ name: 'name' }), option({ name: 'greeting' })],
  settings: { caseSensitive: true },
})

const result = cli.parse(argv.slice(2))
const name = result.arguments.name.value ?? 'World'
const greeting = result.arguments.greeting.value ?? 'Hello'
console.log(`${greeting}, ${name}!`)
```

Run it with Bun, which executes TypeScript files directly:

```sh
$ bun src/cli.ts Alice --greeting Hi
Hi, Alice!
```

With no arguments, the explicit fallbacks apply:

```sh
$ bun src/cli.ts
Hello, World!
```

## Keep argv ownership at the runtime boundary

`parser()` does not read `process.argv` itself. Pass it the exact array for your runtime: Node.js and Bun commonly use `argv.slice(2)`. The parser's default `startIndex` is `0`, so do not pass the full argv array unless you also configure a start index. By default, matching is case-insensitive. Positional and space-separated option values come from the original argv, while values in `--name=value` form are lowercased when `caseSensitive` is false. Set `caseSensitive: true` when option names or equals-form values need exact casing.

The result also includes `raw`, `index`, and `detected` metadata per argument. See [arguments](/docs/args/arguments) to add flags and other input shapes, [commands](/docs/args/commands) for subcommands, or [validation](/docs/args/validation) to validate values that were supplied.
