`@hulla/api` has one shared description and two runtime halves. The contract types both halves, but it performs no I/O and contains no business logic.

<DocsApiArchitecture />

The client side asks for a route. The server side implements it. A transport and adapter meet in the middle to carry that call across the boundary your application actually has.

## Put each decision in one place

| File                            | Runtime     | Put this here                                                   |
| ------------------------------- | ----------- | --------------------------------------------------------------- |
| `src/api/contract.ts`           | Shared      | Paths, inputs, statuses, bodies, errors, schemas, and codecs    |
| `src/api/implementation.ts`     | Server only | Handlers, services, authorization, and server middleware        |
| `src/api/client.ts`             | Caller      | `createClient()`, client middleware, and the selected transport |
| Framework route or server entry | Host only   | Adapter mounting and native request context                     |

The contract is safe to publish as a package or import into browser code. The implementation is not: it can reach databases, secrets, queues, and framework state.

That split is deliberate. A frontend team can compile against the boundary without gaining access to the server module that fulfills it.

## Follow one call

1. **The client selects a route.** The route already knows its method, path, accepted request fields, and possible responses.
2. **Client middleware prepares the call.** It can add auth headers, tracing data, or cancellation without changing the contract.
3. **One transport crosses the boundary.** Fetch serializes HTTP; in-process dispatches locally; MessagePort and WebSocket use their own protocols.
4. **The adapter enters the host.** A native adapter lets Express, Hono, or another framework keep its router and native context. A Fetch adapter matches a Web `Request` itself.
5. **The server validates and runs the handler.** Request fields are decoded before business logic. The handler can return only a declared response or error.
6. **The client receives a typed result.** The status discriminates the body, so checking `result.status` narrows both together.

```ts filename="src/features/projects.ts" focus={1-7}
const result = await api.projects.byId({ params: { id } })

if (result.status === 200) {
  renderProject(result.body)
} else {
  showNotFound(result.body.message)
}
```

There is no generated client and no hidden global router. The client is a typed view of the contract plus a transport.

## Choose the middle boundary

### Use in-process when both sides share a safe server runtime

Server-rendered pages, background jobs, and tests can call the completed implementation without opening a socket. The call still runs validation, middleware, handlers, declared errors, and codecs.

Do not import an in-process client into browser code: it imports the server implementation with it.

### Use Fetch when HTTP is already the boundary

Browsers, services, edge runtimes, and Web-standard routes fit `fetchTransport()` and `fetchAdapter()`. The host owns the origin and deployment; the adapter owns contract matching and conversion.

### Use a native adapter when framework behavior should stay native

Express, Fastify, Hono, H3, Elysia, Koa, NestJS, and full-stack frameworks can keep their router, hooks, parsed bodies, response writer, and request context. The adapter connects those native objects to the portable implementation.

### Use MessagePort or WebSocket for a different process boundary

Workers and desktop shells often already have a port. Long-lived remote clients may already have a socket. These transports preserve the same client call shape without pretending the boundary is Fetch.

## Validation follows direction

A request schema runs on the server after the transport decodes the request. A response schema runs on the server before the adapter sends the response.

The client does not rerun those ordinary schemas. If both sides should work with a richer value than the wire can carry—`Date` in memory and an ISO string in transit—use a codec with explicit encode and decode directions.

Type-only declarations skip application-shape validation altogether. They still use the selected representation, so malformed JSON remains malformed JSON; TypeScript alone does not make untrusted data safe.

## Four rules prevent most mistakes

- Keep framework imports, database clients, and secrets out of the contract module.
- Use ordinary functions when no contract boundary is needed.
- Treat declared non-`2xx` responses as expected values; reserve thrown failures for transport, schema, and unexpected runtime problems.
- Select the smallest contract subtree a client or server module needs.
