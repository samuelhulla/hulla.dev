Install the shared contract first. Then make two separate choices: where the server receives requests, and how the client reaches it.

  <StepperItem id="connect-the-server-boundary" data-toc-section data-toc-label="Connect the server boundary" class="scroll-mt-24">
    <StepperIndicator>2</StepperIndicator>
    <StepperContent>
      <DocsStepperHeading for="connect-the-server-boundary">Connect the server boundary</DocsStepperHeading>
      <StepperDescription>Mount the implementation into the host that receives requests.</StepperDescription>
    </StepperContent>
    <StepperPanel>
      <p>
        A server adapter translates the host's native request into a contract call, provides request context, and
        turns the declared result back into the host's response. Only server code imports this adapter.
      </p>

      - **Web-standard hosts:** use the built-in [`@hulla/api/fetch`](/docs/api/transports/fetch) entrypoint. Follow the [runtime guides](/docs/api/runtimes) for Bun, Deno, Vercel, and other Fetch-compatible hosts.
      - **Native servers:** [`@hulla/api-node`](/docs/api/servers/node-http), [`@hulla/api-express`](/docs/api/servers/express), [`@hulla/api-fastify`](/docs/api/servers/fastify), [`@hulla/api-hono`](/docs/api/servers/hono), [`@hulla/api-h3`](/docs/api/servers/h3), [`@hulla/api-elysia`](/docs/api/servers/elysia), [`@hulla/api-koa`](/docs/api/servers/koa), or [`@hulla/api-nestjs`](/docs/api/servers/nestjs).
      - **Full-stack frameworks:** [`@hulla/api-next`](/docs/api/full-stack/next), [`@hulla/api-tanstack-start`](/docs/api/full-stack/tanstack-start), [`@hulla/api-react-router`](/docs/api/full-stack/react-router), [`@hulla/api-solid-start`](/docs/api/full-stack/solid-start), [`@hulla/api-sveltekit`](/docs/api/full-stack/sveltekit), [`@hulla/api-nuxt`](/docs/api/full-stack/nuxt), or [`@hulla/api-astro`](/docs/api/full-stack/astro).

      <p>
        Install one server adapter in the application that owns the listener or framework route. The shared contract
        package should not depend on Express, Next.js, Node.js, or another host.
      </p>
    </StepperPanel>

  </StepperItem>

  <StepperItem id="connect-the-client-boundary" data-toc-section data-toc-label="Connect the client boundary" class="scroll-mt-24">
    <StepperIndicator>3</StepperIndicator>
    <StepperContent>
      <DocsStepperHeading for="connect-the-client-boundary">Connect the client boundary</DocsStepperHeading>
      <StepperDescription>Choose how typed calls travel from the caller to the server.</StepperDescription>
    </StepperContent>
    <StepperPanel>
      <p>
        A client transport carries a contract-shaped call. It does not mount routes or own server middleware. Most
        applications begin with one of the two transports already included in <code>@hulla/api</code>.
      </p>

      - **Same process:** use [`@hulla/api/in-process`](/docs/api/transports/in-process) in server-rendered code, tests, or another trusted process that can import the implementation.
      - **HTTP:** use [`@hulla/api/fetch`](/docs/api/transports/fetch) in browsers, mobile clients, services, and server-side HTTP calls.
      - **Workers or desktop IPC:** install [`@hulla/api-message-port`](/docs/api/transports/message-port).
      - **Dedicated socket:** install [`@hulla/api-websocket`](/docs/api/transports/websocket).

      <p>
        The client imports the contract and its chosen transport. It imports the implementation only for an
        in-process call—never for Fetch, MessagePort, or WebSocket.
      </p>

      <p>
        Once direct calls work, optionally add [`@hulla/api-control`](/docs/api/integrations/control),
        [`@hulla/api-tanstack-query`](/docs/api/integrations/tanstack-query), or
        [`@hulla/api-swr`](/docs/api/integrations/swr). These wrap an existing client; they do not replace its
        transport.
      </p>
    </StepperPanel>

  </StepperItem>

  <StepperItem id="verify-one-vertical-slice" data-toc-section data-toc-label="Verify one vertical slice" class="scroll-mt-24">
    <StepperIndicator>4</StepperIndicator>
    <StepperContent>
      <DocsStepperHeading for="verify-one-vertical-slice">Verify one vertical slice</DocsStepperHeading>
      <StepperDescription>Prove the contract, implementation, and client before adding framework setup.</StepperDescription>
    </StepperContent>
    <StepperPanel>
      <p>
        Build the first route in process so a listener, proxy, or framework cannot hide contract mistakes. The quick
        start gives you three small modules:
      </p>

      1. `contract.ts` declares and validates what crosses the boundary.
      2. `implementation.ts` contains server-only behavior.
      3. `example.ts` creates a typed client, calls the route, and prints the created task.

      <p>
        When that call works, the core setup is complete. Keep the in-process transport when the caller stays beside
        the server. For a browser or remote caller, move on to the client transport from step 3 and mount the same
        implementation with the server adapter from step 2.
      </p>

      [Build the task API quick start →](/docs/api/quick-start)
    </StepperPanel>

  </StepperItem>
</Stepper>
