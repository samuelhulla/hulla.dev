You will build `POST /api/tasks`. It accepts a task title and returns the created task with an ID and its initial completion state.

This quick start uses one same-process client from beginning to end. That keeps framework and deployment setup out of the first successful call.

Put the contract in a module that both server and client code can import. It describes the request and response, but contains no database access or server startup.

```ts filename="src/api/contract.ts" {4-13,18-23}
import { defineContract, request, response, route } from '@hulla/api'
import { z } from 'zod'

const newTask = z.object({
  title: z.string().min(1),
})

export const task = z.object({
  id: z.string(),
  title: z.string(),
  completed: z.boolean(),
})

export const contract = defineContract({
  basePath: '/api',
  routes: {
    createTask: route.post('/tasks', {
      body: request.json(newTask),
      responses: {
        201: response.json(task),
      },
    }),
  },
})
```

The only input rule is that the title cannot be empty. The route key `createTask` becomes the method you will call from application code.

Keep the implementation in server-only code. The handler receives the validated body and returns the response declared by the contract.

```ts filename="src/api/implementation.ts" {4-12}
import { defineServer } from '@hulla/api/server'
import { contract } from './contract'

export const implementation = defineServer(contract).implement({
  createTask: ({ body, response }) =>
    response(201, {
      id: crypto.randomUUID(),
      title: body.title,
      completed: false,
    }),
})
```

This contract currently contains one route, so this implementation contains one handler. Larger applications can implement and compose smaller contract fragments; the quick start keeps one route together so the request flow stays visible.

Create a client from the same contract. The same-process connection is useful here because it exercises validation, the handler, and the declared response without requiring a web framework or local server.

```ts filename="src/api/example.ts" {6-8,10-14}
import { createClient } from '@hulla/api/client'
import { inProcessTransport } from '@hulla/api/in-process'
import { contract } from './contract'
import { implementation } from './implementation'

const api = createClient(contract, {
  transport: inProcessTransport(implementation),
})

const result = await api.createTask({
  body: { title: 'Write the quick start' },
})

console.log(result.body)
```

The call prints a task shaped like this:

```ts
{
  id: 'generated-id',
  title: 'Write the quick start',
  completed: false,
}
```

You now have the complete path: the contract describes the route, the server handles it, and application code calls `createTask()` from a client built from the same contract.

## Choose the next boundary

Keep this first example intact. Continue with the guide for the application you are actually building:

- Use [HTTP calls with Fetch](/docs/api/transports/fetch) for browsers, services, and Web-standard handlers.
- Choose a [server adapter](/docs/api/servers) when Express, Fastify, Hono, or another framework owns the server.
- Read [Organizing server code](/docs/api/core/server-composition) when the contract grows beyond one module.
- Read [Calling the API](/docs/api/core/clients) for response handling, selections, and client middleware.
