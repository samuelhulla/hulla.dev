`@hulla/control` lets a function return success or failure as a value. Return `Ok` with the data or `Err` with the problem, then let the caller check which one it received.

Using a coding agent? [Install the control skill](/guides/control/quick-start#optional-agent-skill) for package-specific guidance.

```ts
import { err, ok, type Result } from '@hulla/control'

function findTitle(id: string): Result<string, Error> {
  return id === 'welcome' ? ok('Welcome') : err(new Error('Title not found'))
}
```

This is useful when a failure is part of the function's contract, such as a missing record or invalid input. If callers already expect an exception boundary, keep throwing and use [`tcf()` to convert that boundary](/docs/control/attempts). For ordinary internal work with no meaningful failure case, a plain return value is simpler.

Build the [config checker](/guides/control/config-checker) to combine parsing, validation, and error reporting in one small command.

## Choose how to consume the result

| You want to…                                | Use                                                                                         |
| ------------------------------------------- | ------------------------------------------------------------------------------------------- |
| Run different code for success and failure  | [`isOk()` or `isErr()`](/docs/control/results#narrow-when-the-branches-need-different-work) |
| Produce one value from either branch        | [`match()`](/docs/control/results#match-when-both-branches-produce-one-value)               |
| Transform a payload and preserve its branch | [`map()` or `mapErr()`](/docs/control/chaining)                                             |

| Need                                                           | Start here                                 |
| -------------------------------------------------------------- | ------------------------------------------ |
| Install the package and build a first result                   | [Quick start](/guides/control/quick-start) |
| Construct, narrow, and inspect success or error values         | [Results](/docs/control/results)           |
| Transform values while keeping the result branch               | [Chaining](/docs/control/chaining)         |
| Catch exceptions and rejected promises at an explicit boundary | [Attempts](/docs/control/attempts)         |

The result branch carries its own tag (`'ok'` or `'error'` by default), so `Result<string, string>` remains unambiguous. Continue with the [quick start](/guides/control/quick-start) to install `@hulla/control` and call a function that returns both outcomes.
