When a function can fail for a reason its caller should handle, a thrown exception hides that possibility from the return type. This quick start makes the two outcomes explicit: a lookup returns a title on success or an error value when the title is missing.

Install `@hulla/control` in the TypeScript package that will define and call the function:

    bun: 'bun add @hulla/control',

## Return both possible outcomes

In `src/titles.ts`, give the function a `Result` return type. `ok()` wraps a title; `err()` wraps the expected failure. The caller does not need to guess which payload it received.

```ts filename="src/titles.ts"
import { err, ok, type Result } from '@hulla/control'

export function findTitle(id: string): Result<string, Error> {
  if (id === 'welcome') {
    return ok('Welcome')
  }

  return err(new Error(`No title for ${id}`))
}
```

This function is synchronous and performs no I/O. Its result is ready immediately; the next step is to branch on it where the application calls `findTitle()`.

## Handle the branch at the call site

In application code, `isErr()` narrows the value to `Err<Error>`, so TypeScript allows access to `.error`. The remaining branch is `Ok<string>` and exposes `.value`.

```ts filename="src/main.ts"
import { findTitle } from './titles'

const title = findTitle('welcome')

if (title.isErr()) {
  console.error(title.error.message)
} else {
  console.log(title.value)
}
```

This prints `Welcome`. For an unknown ID, it prints `No title for <id>`. The failure stays a normal return value; it does not throw. Learn the available ways to [construct and narrow results](/docs/control/results) before choosing a transformation style.
