Where should a task live? A private draft can stay on the device that created it. A team task needs a server that decides who may read and change it. An app that works on a train can keep both in one SQLite file, with different rules for each table.

## Choose where your data lives

| What you're building                             | Where reads and writes happen                                                                                                  | Start here                                                          |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------- |
| A personal notebook or desktop tool              | The device reads and writes its own SQLite tables, even on first launch offline.                                               | [Local SQLite](/docs/db/sqlite)                                     |
| An API, job, or server-rendered app              | Server code calls PostgreSQL or a SQLite file directly. Your app owns the HTTP routes it needs.                                | [Server-only storage](/docs/db/mental-model#run-only-on-the-server) |
| A shared dashboard that's used online            | The PostgreSQL service executes functions. Browsers subscribe to results in memory.                                            | [Build a live task list](/guides/db/quick-start)                    |
| A field app with shared tasks and private drafts | The service owns shared tasks. Device SQLite stores authorized copies, drafts, and any edits explicitly queued for submission. | [Replicas and offline edits](/docs/db/replication)                  |

All four start with an ordinary TypeScript declaration. Importing this file creates neither a connection nor any rows.

```ts filename="db/schema.ts"
import { defineSchema, defineTable, v } from '@hulla/db'

export const schema = defineSchema({
  tasks: defineTable({ title: v.string() }),
})
```

Pass the schema to the [adapter for the runtime](/docs/db/installation) that owns the data. Two applications can import the same schema and still have entirely independent databases. Sharing rows requires an explicit [source query and replica table](/docs/db/replication).
