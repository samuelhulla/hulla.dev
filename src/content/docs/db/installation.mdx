The adapter APIs in these guides target the **0.3 release line**. Install `@hulla/db` where you author a schema. Install the storage adapter in the application that opens the database. Start with PostgreSQL for your main database. Web and mobile apps can use the generated HTTP client on its own. Add the SQLite adapter to an app that owns local data or stores offline replicas.

## PostgreSQL on a server

<DocsPackageManagerCommand
  commands={{
    bun: 'bun add @hulla/db@^0.3.0 @hulla/db-postgres@^0.3.0',
    npm: 'npm install @hulla/db@^0.3.0 @hulla/db-postgres@^0.3.0',
    pnpm: 'pnpm add @hulla/db@^0.3.0 @hulla/db-postgres@^0.3.0',
    yarn: 'yarn add @hulla/db@^0.3.0 @hulla/db-postgres@^0.3.0',
  }}
/>

For a server route or job, `postgres({ schema, url })` opens existing storage. Use `postgres.initialize({ schema, url })` when provisioning a fresh database. If devices need shared rows, expose [authorized queries and mutations](/docs/db/replication) through the PostgreSQL service. Only the HTTP endpoint and public source declarations belong on the client.

Node and Bun can open a local file. Browser apps provide their own SQLite WASM runtime and persistent storage. Expo apps provide `expo-sqlite`. None of these needs a PostgreSQL server to save local rows. [Save and reopen your first draft](/docs/db/sqlite).

## Local development requirements

The `hulla-db` CLI ships with `@hulla/db`. The managed PostgreSQL workflow requires Node 22.18+ or Bun on a supported native host (macOS arm64 or Linux x64/glibc) with permission to launch subprocesses. The development runtime, compiler, and local PostgreSQL are bundled. The [deployment guide](/docs/db/deployment) covers production host requirements.

For an adapter entrypoint, run `hulla-db dev ./db/server.ts`. With both `url` and `DATABASE_URL` unset, dev provisions its own local PostgreSQL and keeps data under `.hulla/`. To use an existing development database, supply `url` or set `DATABASE_URL`. An explicit URL takes precedence. Provision or migrate external storage explicitly. Outside the dev launcher, the PostgreSQL adapter requires a connection URL.

## Framework bindings

The [live task list quickstart](/guides/db/quick-start) uses the config-based PostgreSQL service and React. In an existing React app, install:

<DocsPackageManagerCommand
  commands={{
    bun: 'bun add @hulla/db@^0.3.0 @hulla/db-react@^0.3.0 zod',
    npm: 'npm install @hulla/db@^0.3.0 @hulla/db-react@^0.3.0 zod',
    pnpm: 'pnpm add @hulla/db@^0.3.0 @hulla/db-react@^0.3.0 zod',
    yarn: 'yarn add @hulla/db@^0.3.0 @hulla/db-react@^0.3.0 zod',
  }}
/>

For Vue, Svelte, or Solid, use `@hulla/db-vue`, `@hulla/db-svelte`, or `@hulla/db-solid`. Match the core release line. A plain TypeScript app can use query subscriptions directly. The [Better Auth adapter](/docs/db/better-auth) and the native [Rust crate](/docs/db/rust) have their own setup.
