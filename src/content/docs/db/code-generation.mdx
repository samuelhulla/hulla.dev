Register your queries and mutations in `db/server.ts`, then generate the client.
The generator reads the registered operation catalogue and produces the TypeScript
imports the browser uses to call it. [Register a query and mutation](/guides/db/quick-start#declare-the-functions).

Use `db.config.ts` as the command argument when the service needs settings such
as allowed origins or an auth verifier. Point its `schema` setting at
`./db/server.ts`. Either command writes `db/_generated/server/` and prints
`Generated database entrypoints.` Storage opens separately when the app starts.
[Service settings](/docs/db/runtime#set-the-listener-and-browser-origin).

## Import the generated surface for your code

| What you're doing                     | Import or file                                               |
| ------------------------------------- | ------------------------------------------------------------ |
| Declare queries and mutations         | `schema.query` and `schema.mutation` from your schema        |
| Call remote operations                | `createClient` from `db/_generated/server/_client`           |
| Run direct operations on the server   | Your adapter instance in `db/server.ts`                      |
| Configure a device replica            | `source` and operation references in `db/_generated/server/` |
| Read or write a local SQLite database | The instance's `db.functions`                                |

Create the generated client once in your app and use `client.functions` from
screens. Exported namespaces become namespaces on that object. A catalogue with
`export * as tasks from './tasks'` lets screens call `api.tasks.list()`.
[Connect the browser client](/docs/db/runtime#connect-browser-functions).

Generation evaluates declaration modules to read their contracts. Keep database
calls and request-specific work inside handlers. Generated clients contain
callable references and type contracts. The service loads the compiled handlers.

## Use the watcher during development

Run `hulla-db dev db/server.ts` alongside your app. The watcher regenerates the
client on source changes and restarts the service. When a service config owns
origins or authentication, run `hulla-db dev db.config.ts` instead.

## Build once, serve prepared artifacts

Run generation during your build and deploy `db/_generated/server/` with your
server code, runtime dependencies and native assets. Start the service with
`hulla-db serve db/server.ts` or pass your service config. Provide the production
PostgreSQL URL in the server environment. The service loads the prepared files
and verifies existing storage before accepting calls.

Keep authored modules outside the generated directory. The generator recognizes
its own output by the ownership header and protects authored files.
